# CI (Lint + Tests) — Design

Phase 5 of the architecture doc's scope
([`docs/superpowers/specs/2026-07-28-fda-device-rag-architecture-design.md`](2026-07-28-fda-device-rag-architecture-design.md)
§8: "GitHub Actions CI running lint + tests on every push/PR"). That's the
entire spec the architecture doc gives — everything else here (test scoping,
lint config, repo setup, Python version) is decided fresh in this document,
verified empirically rather than assumed, per this project's standing bar.

## 1. Test Scoping — Verified Hermetic, No Fixtures Needed

The initial assumption — that the 144-test suite is fully hermetic (no real
corpus, no live Ollama, no network) — was **not** taken on faith. Code
inspection first identified every test file that could plausibly touch a
live dependency (`Embedder`/`SentenceTransformer` construction, HTTP calls,
Ollama). Every one turned out to already be mocked or stubbed:
`test_embedder.py` patches `SentenceTransformer` itself; `test_ollama_client.py`
patches `requests.get`; `test_hybrid_retriever.py`/`test_integration_pipeline.py`
use hand-written `_FakeEmbedder`/`_StubEmbedder` classes (an initial grep for
`Embedder(` false-positived on those class names); `ChromaStore` tests use
`tmp_path`, not the real `data/chroma/`.

That inspection was then checked empirically, not trusted: a fresh
`git clone` into a scratch directory (zero gitignored files — no `data/raw/`,
`data/chroma/`, `data/bm25_index.pkl`) with a brand-new venv ran
`pytest tests/ -q` and produced **144 passed**, matching exactly the
condition a fresh GitHub Actions checkout will be in.

**Conclusion:** CI runs `pytest` against the full suite as-is. No markers,
no skip logic, no committed fixture corpus, no `--deselect` flags. The
scripts that do touch live dependencies (`pull_corpus.py`, `build_index.py`,
`query.py`, `run_eval.py`, `ask.py`, `spot_check_transcripts.py`) have no
coverage of their live IO paths — verified by real runs documented in each
phase's README section, not unit tests — **except `pull_corpus.py`'s
`_fetch_paginated` cross-page dedup logic** (`tests/test_pull_corpus.py`),
which is pure/synthetic-data-based and is already counted in the 144 and
already confirmed hermetic above. That precedent (test the plain logic
embedded in an otherwise-thin wrapper, leave the wrapper itself untested) is
the exact one the citation-grounding design cited to justify testing
`check_ollama_ready` — so there's no live-dependency test to exclude here,
but it's not accurate to say these scripts have *zero* coverage.

## 2. Lint — ruff, Scoped Ruleset

**Tool: ruff**, in the same job as pytest (fail fast on lint before paying
for the test run), added to `pyproject.toml`'s `dev` extra.

**Ruleset, chosen empirically, not by ruff's raw defaults:** an unconfigured
`ruff check .` (this ruff version's actual default rule selection, which is
broader than the classic `E4,E7,E9,F`) surfaced 37 findings across nine
unrelated rule categories — noisy, not a meaningful gate. A conventional
scoped selection (`E` pycodestyle, `F` pyflakes, `I` isort) was tested
instead: 205 findings, of which 178 were `E501` (line-too-long at ruff's
default 88-char limit).

Those 178 `E501` hits were inspected directly, not assumed to be junk: they
are long narrative docstrings and descriptive test-fixture string literals
(e.g. `gold_resolution.py`'s rationale docstrings, `test_sampling.py`'s
inline fixture calls) — this codebase's established, deliberate style
throughout every phase of this project, not unwrapped code needing a fix.
Line-length distribution confirms this isn't a formatting accident: p90 is
77 chars, p99 is 111, max is 206. Reflowing dozens of files to fit an
84-char limit this project never followed would be unrelated churn for zero
functional benefit — exactly the kind of scope creep this project's own
working norms reject.

**Decision: `select = ["E", "F", "I"]`, `ignore = ["E501"]`,
`target-version = "py311"`.** This leaves 27 findings against the current
codebase, all mechanical: 23 unsorted-import blocks, 2 unused imports
(`Section` in `test_sections.py`; `math` in `test_metrics.py` — the latter
is the exact Minor finding the eval-runner whole-branch review flagged and
left unfixed, now closed out for real), and 2 mid-file imports in
`test_metrics.py` (an accepted quirk from that same earlier review, now
worth a trivial fix while touching this anyway). Fixing these 27 (via
`ruff check --fix` for the 25 auto-fixable ones, a 2-line manual move for
the 2 `E402`s) is the plan's first task, so `ruff check .` is genuinely
clean before the workflow file first runs — not asserted clean without
having actually run it.

## 3. GitHub Repository & Push

No remote existed before this phase (`git remote -v` was empty). A new
**public** repo, `fda-device-rag`, is created via `gh repo create` (CLI
confirmed installed and authenticated with `repo`+`workflow` scopes before
this design was finalized), added as `origin`, and `master` is pushed for
the first time.

**Full-history secrets sweep performed before finalizing this design** (not
deferred to "hope nothing's in there"): all 76 commits swept for both
suspicious filenames (`.env`, `credential`, `secret`, `*.pem`, `*.key`,
`token`) via `git log --all --diff-filter=A --name-only` and content
patterns (AWS access keys, `sk-`/`ghp_`/`gho_`-style tokens, private-key
PEM headers, `password=`/`api_key=`-style assignments) via
`git log --all -p` — clean. This matters specifically because it's the
*first* push of the entire history to a public repo: every past commit
becomes visible at once, not just the current snapshot, so a sweep of only
the working tree (as an earlier pass in this session mistakenly did) would
have missed anything added and later removed.

## 4. Workflow

**New file `.github/workflows/ci.yml`.** Single job (`test`), triggered on
`push` and `pull_request` (any branch) — matches the architecture doc's
"every push/PR" requirement exactly.

```yaml
name: CI
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.11"
      - run: pip install -e ".[dev]"
      - run: ruff check .
      - run: pytest
```

**Python version: 3.11 only**, matching `pyproject.toml`'s
`requires-python = ">=3.11"` floor — no matrix. This is the only version
this project has actually been developed and tested against; a matrix would
test compatibility claims nobody has verified, which runs against this
project's "verify, don't assume" norm rather than serving it.

**No secrets, no permissions blocks needed** — openFDA requires no API key,
Ollama isn't touched by any test (per §1), and there's nothing to deploy
from this workflow.

**No dependency caching** for this first pass — not worth the added
workflow complexity until CI runtime is actually annoying in practice.

## 6. Out of Scope

- A Python version matrix (§4) — single-version only, revisit if this
  project ever claims broader compatibility.
- Dependency caching, matrix OS testing, deploy-on-merge automation — none
  of these serve "lint + tests on push/PR," which is the entire stated
  scope from the architecture doc.
- Fixing anything in the codebase beyond the 27 ruff findings from §2 — no
  unrelated cleanup bundled into this phase.
